## Owner decisions that bind this lane (do not reopen)
- Inbound mail is **SES receiving on `in.healdesk.io` under the AWS BAA**. NOT Resend inbound, no receiving key on apps/web, nothing on apps/web at all (SES posts to apps/app directly).
- **Facts only.** The console never shows a clinic's words, and (decided here, consistent with "no inbound text exists" in slice 1) apps/app does **not store the body, the subject text, the sender's display name or attachment file names**. The message is parsed **in memory**, reduced to fixed-list facts, and the raw S3 object is deleted in the same handler. Stored facts only: the matched clinic id (or none), the case ref, source `email`, topic and symptom from the fixed lists in `lib/support/escalation-fields.ts` chosen by a **deterministic keyword classifier** you write (fixed keyword lists per topic/symptom, tested with fixtures; unknown -> topic `other`), urgency from fixed rules (`now` for AYA not answering, calls ringing out, a disputed charge, a lost device, anything about security; else `today`/`this_week` by the existing `replyByDay` rules), counts of what was hidden (numbers, emails, treatment words, clinical matches via `screenText`/`findClinicalContent` run on the body in memory) which set `phi_suspected`, attachment COUNT and coarse type classes (image/pdf/other) and size bucket, the inbound `Message-ID` and `In-Reply-To` (opaque ids, kept for threading), received-at, and the SES verdicts. No `support_messages.text` / `subject_screened` is written for inbound; check migration 0125's constraints and widen only what the new `email` rows need (migration 0129).
- Fixed acknowledgement allowed without approval (owner D14): new email kind `support_received`, Resend, `phiClass: "none"`, fixed template with the case ref only (plus, when `phi_suspected`, one fixed sentence asking that patient details be left out and pointing to Conversations/Bookings in the portal). Sent ONLY to the matched clinic's one sign-in address (never to the From header: no backscatter to strangers), once per case, never for loop-guarded mail, never for the 4th+ mail from one address in an hour, never when DKIM verdict failed. Idempotency key `hd-support_received-<case id>-1`.
- Nothing is sent to any patient. An unmatched sender becomes a case with no clinic, no draft, no acknowledgement; ops matches or closes it (existing `matchSupportCase`/`closeSupportCase`).
- **Never apply anything.** You write Terraform and tests only. No AWS, no `gh workflow run`, no deploy, no vendor call. Run `terraform fmt/validate/test` and tflint/checkov through Docker (`hashicorp/terraform`, etc.) if no local binary; mirror what the `infra` job in `.github/workflows/ci.yml` does and say exactly what you could and could not run.
