## Build
1. **Post**: when a support reply is proposed (the auto-propose hook after a passing draft, `proposeSupportReplyFor`) post ONE message to a configured Slack channel from apps/app (PHI side; new `lib/support/slack-reply.ts`): clinic name, ref, urgency, reply-by day, the draft text (Slack mrkdwn escaped; split over 3000-char blocks), the checks result (names only), and buttons: Review and send (edit, then send), Edit only (save a new draft version without sending), Open in console (link), Snooze 1 day, Close. Use a bot token (`chat.postMessage`; the incoming webhook cannot open dialogs): env `SLACK_BOT_TOKEN`, `SLACK_SUPPORT_CHANNEL`, `SLACK_SIGNING_SECRET`, `SLACK_OPERATOR_IDS` (comma list of Slack user ids allowed to act). All unset = feature off, nothing posted, existing Slack alerts unchanged. Record the message `ts` on the approval item/case (a column, migration 0132 if needed) so a re-draft UPDATES the message (`chat.update`) and an approved/closed/expired item updates it to its final state (buttons removed). Idempotent: one message per (case, draft version).
2. **Interactivity endpoint** `apps/app/src/app/api/webhooks/slack/route.ts` (public host `app.healdesk.io`; the Slack app's interactivity URL): verify Slack's signature (HMAC-SHA256 of `v0:ts:body` with the signing secret, constant time, reject timestamps older than 5 minutes, body size cap, content type `application/x-www-form-urlencoded` payload JSON); 404 when the feature is off; ack within 3 seconds. Only users in `SLACK_OPERATOR_IDS`; anyone else gets an ephemeral refusal and nothing happens (and an ops log with ids only). Actions: **Review and send** opens a modal (`views.open` with the trigger_id) with the reply in an EDITABLE multiline text box (prefilled with the current draft; Slack's input limit is 3000 characters, so a longer draft says 'edit in the console' and offers only the console link and plain Approve of the unchanged draft) and the ref, plus a 6-digit passcode input (type text, never logged); on `view_submission` verify the passcode with the SAME verifier and lockout as the console (shared code, not a copy; the hash must be available to apps/app: a new Parameter Store parameter mirrored by the owner, listed in key-presence and `/admin/map`), then, if the text was edited, save it as a NEW draft version through the same operation the console's Save draft uses (`saveSupportDraft`, which runs the eight reply checks): a failing check re-opens the modal with the rule NAME (never the words) as the validation error and nothing is sent; only a passing edited version is proposed/approved (the approval item must be for exactly that version: re-propose through the existing path, then decide it with the passcode in the same request, atomically enough that a failure leaves no half-approved item); an unchanged text approves the current version. Then call the existing approval decision path with the factor recorded as `passcode via slack` and the Slack user id in the audit actor; show a validation error in the modal for a wrong passcode (no detail about lockout internals beyond 'locked, try later'); the executor's frozen text/hash/label rules and all eight checks are unchanged (the text approved is the text of that draft version; a stale draft version is refused with an update of the message). **Snooze** and **Close** call the existing `snoozeSupportCase` / `closeSupportCase` operations. **Edit only** opens the same text box without a passcode and just saves the new version (checks run; the Slack message updates to the new text). Longer edits and side-by-side facts stay in the console.
3. **Safety**: replay (same `payload` twice) must not double-send (the existing idempotency key and the approval state machine already guard it: prove it); the draft shown in the modal is read from the DB at open time and the approve compares `draft_version` and `approved_hash` at submit; the passcode is checked server-side only; nothing about the passcode or the signing secret in logs; a failed Slack API call never changes approval state; a Slack outage never blocks the console path.
